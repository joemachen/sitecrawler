## What this is

sitecrawler is an SEO site-audit crawler in Python, growing from a single-file
script into a Screaming-Frog-style tool: crawl a site, store every page, report
ranked issues with explanations. Owner: Joe Machen (GitHub `joemachen`), solo
developer, new to formal software process. Joe wants recommended defaults with a
one-line reason, not menus of options.

- Package: `src/sitecrawler/`, Python 3.13, managed with `uv`

## Where things stand

Phase 0 (foundation) and Phase 1 (core crawl and storage) are complete and on
`main`, released as v0.2.0. CI is green on Ubuntu, Windows and the docs build.
Phase 1 landed as four squash-merged PRs (#5 fetcher, #6 store, #7 list mode,
#8 export) plus a release PR.

What exists now:

- `sitecrawler crawl URL [-o pages.csv] [--db crawl.db [--resume]]`: httpx +
  asyncio fetcher, per-host throttle, every redirect hop recorded,
  `redirect_loop` outcome, sitemap seeding, robots.txt.
- `sitecrawler list urls.txt|- [--follow]`: fetch exactly the given URLs on any
  hosts; robots and delay per host.
- `sitecrawler export crawl.db --format csv|xlsx|json`.
- SQLite store (`store/`): one crawl per file; tables `crawls`, `pages`,
  `redirect_hops`, `page_html`, `links`, `sitemap_urls`. `pages.state`
  pending/done is the resume mechanism. The crawler talks to it through the
  `CrawlSink` protocol in `crawl/sink.py`, so `crawl/` never imports `store/`.
- 117 offline tests, ~98% coverage. ADRs 0001-0004. User guide pages: crawl,
  storage, list-mode, export.

## Decisions already made (do not re-open)

| Decision | Choice |
| --- | --- |
| Interface | CLI first; local web UI (FastAPI + Jinja2 + HTMX + Tabulator) arrives in Phase 3 |
| Storage | SQLite, one file per crawl, via SQLAlchemy 2.0 (ADR-0004) |
| HTTP | httpx + asyncio, redirects followed by hand, per-host throttle (ADR-0003) |
| HTML | lxml (+ cssselect) once custom extraction lands; BeautifulSoup today |
| JS rendering | Playwright headless Chromium, Phase 4 |
| Issues engine | Rule classes with id, severity, category, summary, why, fix; docs generated from them |
| Commits | Conventional Commits, squash-merge PRs, `CHANGELOG.md` entry per change |
| List mode | URLs may span hosts; `--follow` stays within the listed hosts |
| Resume | `pages.state` is the frontier; `max_pages` counts across runs; `crawls.status` is `stopped` when capped |

Full rationale in `docs/adr/`.

## Gotchas learned the hard way

- **`localhost` is IPv6-first on this machine.** Every connection to
  `localhost` stalls ~2 s before falling back to 127.0.0.1. The test server
  binds to `127.0.0.1` explicitly via `httpserver_listen_address` in
  `tests/conftest.py`. Keep it that way.
- **mabelslabels.com blocks after a full crawl.** After the 1,691-page crawl on
  2026-10-21 the site returned 503 from its AWS load balancer with
  `Retry-After: 3600`, even to a browser User-Agent. Use a longer `--delay`
  (1 s or more) there and verify it answers 200 before relying on it.
- **Crawl `depth` is first-discovery depth, not shortest path.** With more
  than one worker it varies run to run. Integration tests use `workers=1`.
  Shortest-path depth comes from the link graph in Phase 7.
- **Rich wraps console output to the terminal width**, which is narrower on
  Linux CI than on Windows. Tests that look for a phrase in CLI output must
  compare with whitespace collapsed (`" ".join(output.split())`).
- **Redirect targets are requested as hops.** A test asserting "page X was
  not re-fetched" must exclude pages that other pages redirect to
  (`_REDIRECT_TARGETS` in `tests/integration/test_store_crawl.py`).
- **Never point a test at a real hostname.** An "off-site" redirect test must
  target a second local `HTTPServer`, or DNS gets involved.
- **Windows holds SQLite files open until `engine.dispose()`.** Always use
  `with open_store(...)` in tests and close before re-opening or deleting.
- **gitignore does not allow trailing comments on a pattern line.** Comments
  go on their own line.
- **Run interpreters on downloaded content with `python -I`** and keep crawl
  output out of git (`*.csv`, `*.db`, `*.log` are ignored).
- The Bash tool on this Windows machine mangles heredocs containing
  apostrophes; use the Write tool for files, or a Python script for edits.
- `-q` in `pytest` addopts plus `-q` on the command line gives `-qq`, which
  hides the pass/fail summary line.
- Dependabot's uv is older than ours: its grouped lockfile PRs can downgrade
  packages. Read the lock diff before merging.
